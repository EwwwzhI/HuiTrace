# HuiTrace interface languages

HuiTrace now supports English and Simplified Chinese as an offline interface
preference. The preference is separate from transcription and summary language.

The frontend keeps the language files in `frontend/src/i18n/en.json` and
`frontend/src/i18n/zh-CN.json`. `translateUI()` is safe to use from shared
formatting and server-rendered code; `useUiTranslation()` subscribes client
components to language changes so a switch updates the current screen without
reloading the route or discarding an in-progress form.

The choice is stored in both local browser storage (for the static web preview)
and the Tauri Store (`ui-preferences.json`) for the desktop app. `system` uses
the first browser/OS language and falls back to English. Unsupported values also
fall back to `system`.

The native command `set_ui_language` updates the tray menu and native recording
notifications. The current native process keeps the selected language in memory;
the frontend restores it from the Tauri Store during startup.

The current pass covers the main navigation, settings, onboarding, recording,
import, transcript, summary, speaker, model, update, recovery, consent, and
error surfaces. New user-visible copy should use an English key in both JSON
files and call `translateUI()` or `useUiTranslation()`. Meeting titles,
transcripts, summaries, model names, file paths, and provider responses remain
user/content data and are not translated.

Validation on 2026-09-11: language switching was exercised in the local settings
page in both directions; 33 frontend test files / 224 tests passed; the Next.js
static production build passed; and the native Rust library check passed with
the CPU/no-default-features profile.
