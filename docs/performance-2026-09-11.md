# HuiTrace 页面性能测量与优化（2026-09-11）

本次完成开发前端启动与生产前端会议页的测量、优化、回归验证。未测量 Tauri/WebView2 原生冷启动、Rust 编译、真实 SQLCipher 查询或 AI 模型推理，因此不能将以下数字称为完整桌面应用启动成绩。

## 测量条件

- Windows，本机生产静态导出，Codex 内置 Chromium 浏览器，HTTP loopback，响应 `Cache-Control: no-store`。
- 独立端口 3219；脚本注入模拟 IPC，完全不连接原生后端。会议含 1000 条合成转录，首批 100 条，元数据/转录/摘要读取固定模拟延迟 80ms。
- 摘要为只读 Markdown 旧格式，测量正文出现；不是可编辑 BlockNote 或结构化审批界面的基准。
- 指标由 DOM 变化后 requestAnimationFrame 记录；这是接近显示时机的代理值，不是浏览器实际呈现帧或完整可交互时间。
- 前后各取 5 次同进程重复 reload；未清除浏览器编译缓存或 OS 文件缓存，没有 CPU/网络节流。环境负载未锁定，小幅变化不宜作统计显著性结论。
- 模拟层未覆盖所有后台读取，部分无关设置显示不可用/恢复提示。这些提示不是原生应用回归结果。浏览器操作只验证路由和窗口渲染，没有录音、导入或写入真实会议。

## 生产前端结果

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| 转录面板出现，中位数 | 174.7ms | 164.4ms |
| 摘要正文出现，中位数 | 298.3ms | 284.9ms |
| 正文出现后的采样点，JS 解码字节 | 3,494,555 | 3,460,724 |
| JS 资源数量（含测试探针） | 60 | 61 |
| 上述样本观察到 >50ms 主线程任务 | 0 | 0 |

转录约降低 5.9%，摘要约降低 4.5%，JS 约降低 1%。收益有限，不能宣称消除了所有卡顿。资源字节是在周期采样点取得，未包含尚未完成的后台资源。

原始数组见 `output/performance/baseline-meeting.json`、`final-meeting.json`。最终构建首次 reload 的慢样本也保留：转录 474.1ms，摘要 1072.3ms；没有将它混入“热进程重复加载”比较，也没有证明首次冷加载得到改善。中间曾尝试提前解析 React.lazy Promise，出现约 300ms 额外等待，该实现已替换；摘要代码额外预取也未保留。

设置导航另测一次约 67.5ms 至标签栏出现，没有对应基线，不能宣称提速。已通过浏览器确认新懒加载音频导入窗口能显示选择文件、取消按钮；没有选择文件或执行导入。

## 开发前端启动

每次启动独立 Next dev 进程及独立编译目录，不重启现有 Tauri 会话。单次测试结果：

- 原逻辑，四页全部预热完成再放行：28,664.6ms。
- 新逻辑，首页完成即可放行：9,321.1ms；同一轮其余路由于 23,011.6ms 完成。
- 有一轮同时跑生产构建的样本（14,642.3ms / 32,221.4ms）受 CPU 竞争影响，单独保留在 `dev-after.json`，不用于结论。

该结果说明等待的位置改变了，并不代表所有编译工作都消失。首页就绪后立刻访问尚在后台编译的页面仍可能等待；后台编译也会消耗 CPU。正式静态应用不运行此开发预热脚本。

## 保留的改动

1. `tauri-dev-server.js` 只将首页和完整脚本两轮检查作为启动前置条件，其他三页后台处理；后台失败只报告警告，首页失败仍阻止启动。
2. 会议详情组件下载与元数据/首批转录 IPC 并行。模块就绪后直接渲染，保留骨架屏、组件代码缓存、失败重试以及会议切换取消保护；不预加载会议内容、不自动生成摘要。
3. 音频导入窗口与首次引导组件按需加载，导入遮罩从具体模块导入。
4. 开发默认缓存移至 `.next-dev`。Next 15 的 `output: export` 会将自定义 distDir 解释为静态导出位置，内部仍使用 `.next`，因此仅设置生产 `.next-verify` 不足以隔离开发缓存。这个行为已由本地 Next 源码核实。

## 验证与复现

- 生产构建通过；TypeScript 通过。
- 启动预热 6 项测试通过：包含首页失败、后台失败、放行顺序、截断脚本重试和 HMR 转发。
- 会议切换/慢摘要、设置标签保留、转录分页及 ConfigContext 共 9 项测试通过；最终页面加载修改后相关 6 项再次通过。

在 `frontend` 目录执行：

```powershell
$env:NEXT_DIST_DIR='.next-verify'
pnpm build
node scripts/performance-server.cjs
```

浏览器打开 `http://127.0.0.1:3219/meeting-details?id=perf-meeting`；等待隐藏元素 `#__perf-result[data-complete="true"]` 后读取其 JSON。重复 reload 收集样本。脚本只由独立服务器注入，不会进入正式构建。结束时 Ctrl+C 关闭服务器。

开发冷编译测试：`node scripts/measure-dev-startup.cjs after-check`。新脚本每次使用带时间戳的独立缓存目录；`before` 参数比较原先的四页阻塞策略（源码仍是当前优化版本，不能重新生成历史源码基线）。单独运行，避免与生产构建或模型推理并发。

后续若要宣称桌面端完整优化，还需要独立测试配置下的 WebView2/真实数据库计时、首次冷加载和大会议交互分析；当前证据不支持重构缓存或扩大页面预热范围。
